# dns01 — Pi-hole (10.0.2.7)

Raspberry Pi Zero W, Raspbian 12 armv6, Pi-hole v5.18.2 / FTL v5.25.2 installed by the
official installer (not apt). Blocky's upstream and the secondary resolver. Role:
`roles/services/network/pihole`, playbook `playbooks/hosts/dns01.yml` (deployed by Gitea CI).

## What Ansible owns

| Thing | Where | Variable |
|---|---|---|
| Conditional forward `puhome.net` -> Blocky | `/etc/dnsmasq.d/02-puhome-forward.conf` | `pihole_forward_*` |
| Selected `setupVars.conf` keys (DNSSEC, upstreams, listening, ...), one `lineinfile` per key | `/etc/pihole/setupVars.conf` | `pihole_setupvars` |
| FTL settings (MAXDBDAYS=30, PRIVACYLEVEL, RATE_LIMIT) | `/etc/pihole/pihole-FTL.conf` | `pihole_ftl_conf` |
| Adlists | `gravity.db` `adlist` | `pihole_adlists` |
| Exact allowlist (type 0) | `gravity.db` `domainlist` | `pihole_allowlist` (= `dns_allowlist`) |
| Regex allow (type 2) / regex deny (type 3) | `gravity.db` `domainlist` | `pihole_regex_allowlist` / `pihole_regex_denylist` |
| Absent: manual `07-root-ksk-2024.conf` | `/etc/dnsmasq.d/` | - |

The list sync is **declarative**: adlists, and domainlist types 0/2/3, not in the vars are
deleted. Exact denylist (type 1) and groups/clients are not touched. Set
`pihole_manage_lists: false` to stop managing lists.

## What is left alone

- `WEBPASSWORD` and every `setupVars.conf` key not in `pihole_setupvars` (never put the
  hash in the repo; the file is never templated whole).
- The installation itself and the Pi-hole version. v5.18.2 is outdated vs v6; it is
  deliberately not upgraded here.
- `/etc/dnsmasq.d/01-pihole.conf` is generated by Pi-hole from setupVars; never edit it.
- The weekly gravity cron (Sun 03:57) and the `pihole-FTL.db` query database.

## How changes are applied

- setupVars key changed -> handler runs `pihole -a -i <DNSMASQ_LISTENING>`, Pi-hole v5's
  CLI route to `ProcessDNSSettings` (rewrites `01-pihole.conf`: `server=`, `dnssec` +
  `trust-anchor=`, `bogus-priv`, ...) and restarts DNS.
- FTL conf / drop-in changed -> `pihole restartdns` (FTL reads its conf only at start).
- Adlists changed -> `pihole -g` (async, up to 1 h; roughly 6 min on the weekly run).
- Allow/regex lists changed -> `pihole restartdns reload-lists`.
- gravity.db is edited with `pihole-FTL sqlite3` (the `sqlite3` package is not installed);
  Pi-hole's own triggers add the group-0 membership for new rows.

## Add / remove an adlist or allowlist entry

Edit `pihole_adlists` (role defaults) or `dns_allowlist` (`hosts/group_vars/all/vars.yml`,
shared with Blocky), push, let CI apply. Never `pihole -w` / `-b` / web UI by hand: the next
run reverts it.

## DNSSEC is off

`DNSSEC=false`. The root-KSK rollover (Oct 2026) broke local validation, which was worked
around with a temporary `07-root-ksk-2024.conf`; now removed. The upstream resolvers
(Google, Cloudflare) validate, so validation still happens one hop up.

## Rebuild dns01 from scratch

1. Flash Raspbian 12, set 10.0.2.7, add the Ansible user/key (`init.yml`).
2. Preseed `/etc/pihole/setupVars.conf` with the managed keys from `pihole_setupvars`
   (plus `INSTALL_WEB=True`, `WEBUIBOXEDLAYOUT=traditional`, `TEMPERATUREUNIT=C`,
   `API_QUERY_LOG_SHOW=all`, `API_PRIVACY_MODE=False`, `REV_SERVER=false`) and a
   `WEBPASSWORD` of your choosing (set it on the Pi only).
3. `curl -sSL https://install.pi-hole.net | sudo bash /dev/stdin --unattended`
   (this installs the current release; pin v5.18.2 via `/etc/pihole/ftlbranch` /
   `pihole checkout` if v5 is required).
4. Run the playbook (push and let CI apply, or re-run the dns01 deploy). The first run
   inserts all adlists and runs `pihole -g`.

## MAXDBDAYS=30 does not shrink the DB

It only makes FTL delete rows older than 30 days. The existing `pihole-FTL.db` (~4.3 GB)
keeps its size until a one-time `sudo systemctl stop pihole-FTL`, `sqlite3`/`pihole-FTL
sqlite3 /etc/pihole/pihole-FTL.db VACUUM` (needs free space about the DB size) or deleting
the file, then start FTL. Left to the owner.
